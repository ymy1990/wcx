# 密友功能修复说明

当前维护分支已合并至 WCX v303，入口沿用「功能 → 密友功能」。下方保留 v294 测试版及早期 v287 的发布记录。

## 朋友圈开关独立生效修复（2026-10-15，本地）

旧「隐藏联系人」还安装了帖子、新动态红点和内联点赞/评论过滤；主页会话隐藏与主页搜索复用的通用 SQL 规则也包含 `SnsComment` 过滤。因此即使两个朋友圈开关均已关闭，仍可能隐藏密友帖子或互动。此外，旧「朋友圈隐藏」本身会连带过滤点赞/评论，与互动开关的独立含义不符。

现在移除旧入口的朋友圈过滤及通用规则中的互动过滤，所有帖子过滤只归「朋友圈隐藏」，所有内联点赞/评论和互动消息列表过滤只归「朋友圈互动隐藏」。互动消息由该开关独立安装原生 SQLite wrapper 与数据库查询监听，覆盖会话隐藏关闭时的查询路径；关闭、总开关关闭或临时显示时放行。过滤只影响查询/渲染，内联数据仍在克隆体上处理，不删除或改写原始朋友圈记录。

| 朋友圈隐藏 | 朋友圈互动隐藏 | 预期行为 |
| --- | --- | --- |
| 关闭 | 关闭 | 两类内容均不被这两个密友功能过滤 |
| 开启 | 关闭 | 隐藏密友帖子及其新动态红点，共同好友帖子下的密友互动保留 |
| 关闭 | 开启 | 保留密友帖子，隐藏密友点赞、评论及互动消息 |
| 开启 | 开启 | 帖子与互动分别隐藏 |

保留原开关名称、存储键、默认值与现有设置，迁移仍不覆盖明确保存的关闭值。更新后需重启微信并重新进入朋友圈，让旧进程安装的过滤和已渲染列表失效。本次设备尚未连接，四种组合的实机验证待完成；此本地修复不自动更新 GitHub Release。

## v303 未读提示残留修复

旧实现仅从收到消息或查询结果追加提示，微信未读数归零后没有核销旧标记；查询又依赖结果字典的列名和数值类型，日志可能显示数据库已就绪但未成功读到会话。因此旧提示可能长期保留。

提示改为逐密友与微信原生会话的未读数对账，包含免打扰未读数；原生接口不可用时按 SQL 游标列位置读取，避免依赖列名大小写。确认已读后清除对应标记，查询失败或无法确认时保留；新消息回调后留出更新窗口，避免旧查询误清刚收到的消息。打开对应对话仍立即清除，回到主页不清除其他未读会话。此过程只更新模块提示，不将微信消息标记已读。

总开关关闭时只暂停视觉提示，不清空保存的未读标记；移出名单时才移除对应标记。绿色显示状态点及两个独立恢复开关保持原有逻辑。

## v303 初始化卡顿与会话列表无响应修复

实机线程记录显示，Hchat 的快捷已读初始化停在 `WeChatDatabaseApi.storageObjectForMethod`。旧代码没有对象数、深度或耗时限制，且在出队时才去重，会沿着 CoreStorage 引用遍历应用/虚拟机对象、展开大数组和重复引用。该问题在未读提示修复前的 3545148 已有触摸响应超时记录；后续诊断包再次复现，进程驻留内存约 2.3GB。

现在优先复用 WCX 已解析的原生会话存储。兜底对象查找及数据库 wrapper 查找统一限制为 512 个对象、4 层、每节点 128 个候选和约 100ms；入队时去重，跳过基本类型数组、不可用的标量以及 Context/View/Thread/ClassLoader 等无关对象图。暂未找到时返回未就绪，允许后续重试，不进行无上限的扫描。

包含临时线程诊断的 3545151 已验证初始化完成、会话列表可滑动、未读为零时提示关闭。最终交付包移除临时全线程采样，保留上述功能修复。

## 本次修复

- 统一标题多击与长按手势处理，减少微信标题双击行为及标题视图重建对触发的影响。
- 临时显示密友后，进入对话继续保持显示；退出任意对话回到主页时，由「离开对话恢复隐藏」控制恢复。
- 「离开主页/切走微信恢复隐藏」独立控制离开主页、按 HOME 或微信转入后台后的恢复。两个恢复开关可以分别使用。
- 已处于隐藏状态时跳过重复恢复提示；操作提示缩短为约 1 秒。
- 加粗与圆点根据密友未读消息显示，打开对应密友对话或原生未读数确认为零时清除；返回主页或打开其他对话保留其他未读会话的提示。
- 「密友显示状态提示」默认开启，临时显示密友时在原未读圆点的位置显示绿点，恢复隐藏后消失；红点和绿点共用大小。绿点只表示显示状态，不清除密友未读记录，且不受「圆点提示」开关控制。
- 保留定时显示/隐藏和自动拒绝音视频通话，并提供独立开关。
- 保留密友名单及相关配置，兼容原组合恢复设置和旧标题多击设置；隐藏处理不删除会话记录，也不主动清空原生未读数。
- 修正可选 DEX 目标未解析时的占位方法识别，避免错误安装 Hook。
