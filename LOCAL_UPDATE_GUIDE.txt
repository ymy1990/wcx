平时使用：
1. 先让你的 GitHub fork 更新到想使用的 WCX 版本。
2. 双击 D:/projects/VX/output/更新密友版.cmd。
3. 脚本拉取 fork、保留当前分支作为备份、合并新提交，再编译本地签名 APK。
4. APK 输出到 D:/projects/VX/output/maintenance。
5. 手机连接后验证标题三连击、两个恢复开关、收到密友消息及打开对应对话后的提示清除，再使用新包。

PowerShell 用法（在工作副本中）：
./Sync-WcxLocal.ps1 -CheckOnly   只检查更新，不合并或编译
./Sync-WcxLocal.ps1              更新、合并并编译
./Sync-WcxLocal.ps1 -BuildOnly   只编译当前源码，用于修复冲突后重新构建
./Sync-WcxLocal.ps1 -SkipBuild   更新和合并，不编译

遇到冲突：
脚本会停止并列出冲突文件，不会自动用某一方覆盖，也不会继续输出未验证的新包。
解决冲突并 git add/git commit 后，运行 -BuildOnly。
取消本次合并用 git merge --abort；每次需要合并前会建立 codex/wcxlc-backup-时间 分支。
当前有未提交修改或未完成合并时，更新会停止；先保存当前工作。

版本与签名：
源项目保留自己的版本号；wcxlcVersionCode/wcxlcVersionName Gradle 属性仅用于本地构建。
本地版本号会递增，版本名跟随基础版本，例如 v285-wcxlc-local。
脚本沿用此前的本地签名文件，签名密钥不会加入 Git 提交或备份 bundle。
编译成功、生成注册表至少含 36 项及两个独立恢复控制、APK 元数据与签名验证通过后才交付 APK。
如果未来源码、构建工具或微信接口变动，可能需要手动调整和实机验证；Git 合并成功不代表所有场景自动兼容。
